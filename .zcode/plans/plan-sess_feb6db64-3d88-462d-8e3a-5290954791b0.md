# System-Design Hardening — Full Batch

## Research result (why these fixes)

Three deep sweeps (backend runtime, DB/audit state, infra/delivery) found ~25 real-world problems. The order/payment core is already solid (atomic stock, capture lock, webhook dedupe, idempotency). The remaining real-world debt:

**Critical (fix in code):**
1. `server/middleware/adaptiveRateLimit.js:4-28` — unbounded in-memory Map, keyed partly by full `req.originalUrl` **including query string**; applied to all payment routes → OOM vector during bot storms.
2. `server/services/statusService.js:465-513` — status-email outbox is find-then-save (check-then-act); api + worker containers both run it → duplicate subscriber emails. Other workers already claim atomically; this one doesn't.
3. `server/middleware/metrics.js:189-192` — unmatched/404 paths become raw Prometheus route labels → unbounded metric cardinality (heap bloat, slow scrapes).
4. `server/services/orderPlacementService.js:305-313` — `User.lifetimeSpent` is a float `$inc` accumulator (audit risk #1: the live money-drift site).
5. `infra/aws/docker-compose.ec2.yml` — no docker log rotation on a 20GB prod disk → guaranteed disk-fill outage; **no production Mongo backup at all** (audit risk #9; DR runbook admits RPO 24h).
6. Unbounded memory in `catalogService.productIdentifierCache` and `performance/cache.js` memory provider; Gmail SMTP transport has no timeouts (can wedge the order-email worker for 5 min).

**Also fixing:** per-request Atlas-search probe + unanchored regex fallback (circuit-break it), monitor alert dedupe (no unique index → duplicate admin alerts), `unhandledRejection` swallowed (`server/index.js:1000-1005`), `req.rawBody` captured on every JSON request, global rate limiter Redis-fallback observability, CloudFront SPA deep-link breakage, over-broad Capacitor `allowNavigation`, no external uptime probe.

## Work items (~16 conventional commits, new branch stacked on PR #457)

**Group A — Runtime safety (server/):**
- A1 `adaptiveRateLimit.js`: strip query from key (`originalUrl.split('?')[0]`), cap Map size (env-tunable) with eviction + periodic expired-bucket sweep; keep test helper.
- A2 `catalogService.js`: cap `productIdentifierCache` (max entries + sweep; reuse `chatQuotaService.js` pattern).
- A3 `performance/cache.js`: memory-provider entry cap + LRU eviction.
- A4 `metrics.js`: unmatched routes → fixed `unmatched` label.
- A5 `gmailProvider.js`: `connectionTimeout`/`greetingTimeout`/`socketTimeout` (mirror resendProvider's 15s).

## Known repo gotchas to respect
- Mixed-EOL trap on server files: check EOL vs `git show HEAD:<path> | file -`, normalize before staging.
- New test suites must be triaged into `config/test-tiers.json` (verify: `node scripts/check-test-tiers.cjs`).
- Payment-strict tests must pin `paymentFlags`; CI exports `PAYMENT_PROVIDER=mock`.
- Doc scanner false-positives when "staging" is paired with prod-infra terms — word backup docs carefully.
- Infra scripts are written but cannot be executed locally (no AWS access) — verified structurally + by CI; stated as residual risk.

## Verification ladder
- Per-commit: `npm --prefix server test -- --runTestsByPath <touched test files>`.
- After groups A–D: full `npm --prefix server test` (shared middleware/services touched) + `node scripts/check-test-tiers.cjs`.
- `npm --prefix app run build` if `app/` touched.
- Push branch, watch CI green, then PR (stacked on #457) with verification matrix + residual risks.

## Residual risks (documented, not fixed here)
Hardcoded CloudFront domain across ~50 files (deferred — needs custom-domain decision), exposed Firebase key rotation (owner action), single-host prod topology, Mongo version skew, float majors full deprecation (dual-write transition continues), no ASG/Elastic IP/managed Mongo.
