## Database deep-research audit + real-world fixes

**Research verdict:** MongoDB/Mongoose (~60 models in `server/models/`) + Redis (volatile). Core commerce paths are unusually well-hardened (transactions, minor-unit money, idempotency store, outbox, refund locks), but research found real, ranked problems. Full audit report will be written to `docs/` as the final commit.

### Fixes (7 logical conventional commits on new branch `fix/db-real-world-hardening` off `main`)

**1. `fix(payments): serialize capture`** — `server/services/payments/paymentService.js`
`captureIntentNow` (line 1461) is check-then-act: outbox worker (line 2114), admin route, and listing-escrow route can capture concurrently → double provider capture + Mongoose VersionError leaves a paid order unpaid. Fix: add `acquireCaptureLock`/`releaseCaptureLock` mirroring the existing refund lock (`metadata.captureLock`, 2-min TTL), re-check status under lock, persist via conditional `findOneAndUpdate({ _id, status: 'authorized' }, ...)`; already-captured becomes idempotent success. Lock released in `finally`.

**2. `fix(loyalty): atomic point awards`** — `server/services/loyaltyService.js:166-189`
Read-modify-write `user.save()` loses points under concurrent orders/logins. Replace with atomic `User.updateOne({ $inc: { 'loyalty.pointsBalance', 'loyalty.lifetimeEarned' }, $push: { 'loyalty.ledger': { $each, $position: 0, $slice: MAX } }, $set: { tier, lastEarnedAt } })` (session-aware). For `daily_login`, add a conditional filter on `lastDailyRewardAt` so two concurrent logins can't both award; `modifiedCount === 0` → not awarded.

**3. `fix(catalog): Product.id integrity`** — `server/models/Product.js:87`, `server/services/catalogService.js`
`Product.id` (drives stock decrement at `orderPlacementService.js:126`, carts, price alerts) is indexed but **not unique**, and the write-blocked fallback allocator (line 1419) can mint duplicates. Fix: make `id` unique; fallback probes for a free id; `createManualProduct` retries once on `id` duplicate-key. `deleteManualProduct` (1531) hard-deletes and orphans reviews → archive (soft-delete) when `ProductReview` references exist, else hard delete. New dry-run-default migration `server/scripts/migrate_product_id_unique.js` (+ npm script) to audit duplicates and create the unique index for production (autoIndex is off there).

**4. `feat(coupons): once-per-user redemption ledger`** — new `server/models/CouponRedemption.js`
Coupons are a static config (`server/config/coupons.js`) reusable forever. Add `CouponRedemption` with unique `{ code, user }` backstop; enforce inside `executeOrderCreation` (inside the placement transaction when available): pre-check + insert redemption in same tx, E11000 → 409. Config gains `maxUsesPerUser: 1`. Works on the non-transaction fallback path too.

**5. `feat(retention): TTL for telemetry`** — `server/models/SearchEvent.js`, `RecommendationEvent.js`
Both grow forever (one doc per search/interaction). Add env-overridable TTL indexes on `createdAt` — `SEARCH_EVENT_RETENTION_DAYS` / `RECOMMENDATION_EVENT_RETENTION_DAYS`, default 90 — with a doc note that changing the value requires index rebuild.

**6. `fix(server): webhook dedupe, shutdown, regex`** — `paymentService.js`, `index.js`, `config/redis.js`, `commerceIntelligenceService.js`, `bundleService.js`
Wrap `PaymentEvent.create` sites in a helper that catches E11000 → return `{ deduped: true }` instead of a 500 on concurrent webhook deliveries. Graceful shutdown (index.js:959) currently never stops the outbox `setInterval` or closes Redis → add `stopPaymentOutboxWorker()` + `closeRedis()` and call both. Escape regex special chars in the unescaped fuzzy regexes (`commerceIntelligenceService.js:203,302`, `bundleService.js:12-14`) — user-typed keywords with `()*+?` currently throw or force full scans.

**7. `docs: database audit report`** — `docs/database-audit-2026-09-07.md`
Architecture map (engines, 60 models, migration story, retention), the ranked findings, what this batch fixed, and residual risks left open (float majors alongside minor units, string-typed cross-refs, Mixed-typed blobs, per-process cache invalidation across instances, no migration framework, 260 untriaged suites, prod backup automation gap, Mongo version skew across 4 environments, unbounded User embedded arrays, SecurityEvent retention policy).
