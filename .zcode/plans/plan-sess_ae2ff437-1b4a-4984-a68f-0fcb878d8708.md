# Auth Incremental Refactor — Security Gaps First

## Research verdict (what you asked: "good or worst?")

**Good — keep it, harden it. Do NOT rewrite.** The backend auth is Firebase Auth (ID-token verification with revocation checks) + a custom HttpOnly/Secure/SameSite cookie session layer (Redis-backed, idle/absolute TTL) with WebAuthn passkeys, encrypted TOTP secrets, recovery codes, RSA-PSS trusted-device keys, login lockout gates, distributed/adaptive rate limits, Turnstile, and admin step-up policies. Scale: `authMiddleware.js` 1,912 lines, `authController.js` 2,366 lines, `browserSessionService.js` 1,634 lines; 120 of 358 server test files are auth/security; CI runs gitleaks/semgrep/Trivy/ZAP + a 437-check `security:all` runner. The 2026-06-01 audit (`SECURITY_ARCHITECTURE_REVIEW.md`) scored auth 8/10 ("unusually strong"). A ground-up rewrite would rework ~120 test files for zero security gain — rejected.

**The three real gaps found (verified in code, not just docs):**
1. **P0 — Unfinished secret rotation:** `ROTATE_SECRETS_REQUIRED.md` — a Firebase/GCP API key was historically committed (`app/android/app/build.gradle`, `app/.env.production` in old commits); the owner verification checklist has blank dates (rotation never confirmed).
2. **P1 — Token blast radius:** Firebase tokens persist in localStorage (`browserLocalPersistence`, `app/src/config/firebase.js:245`); production CSP allows `localhost` connect-src (`vercel.json:48`, `app/vercel.json:46`, `netlify.toml:8`) — both widen XSS impact.
3. **P2 — No central route-security proof:** audit's "fix this month" item — route security is manually composed per-route file; no matrix test proves every state-changing route has auth/CSRF/validation/rate-limit guards.

## Phase 1 — Secrets hygiene (P0)
1. If missing, add `.env*` (incl. `.env.aws-secrets*`) to `server/.dockerignore` (audit 24-hour item; verify first — may already be fixed).
2. Grep the working tree for the historically exposed key patterns (`app/android/app/build.gradle`, `app/.env.production`) — flag presence only, never print values.
3. Re-run `npm run security:gitleaks` and `npm run security:secrets`; confirm fail-closed on new findings.
4. Convert `ROTATE_SECRETS_REQUIRED.md` into a concrete owner runbook: exact Firebase console steps (delete/restrict key, add Android package+SHA1 / HTTP-referrer restrictions), placeholders for dates. **I cannot rotate console secrets — owner executes; stated limitation.**

## Phase 2 — Token blast radius (P1)
1. `app/src/config/firebase.js`: `browserLocalPersistence` → `browserSessionPersistence`. Tradeoff stated up front: login no longer survives a full browser restart (Firebase re-prompts); reversible one-liner. Update AuthContext/authSessionState tests that assume persistence.
2. CSP: remove `localhost` from **production** `connect-src` in `vercel.json` / `app/vercel.json` / `netlify.toml` — only after verifying the desktop shell doesn't consume web-host CSP (check `desktop/` build pipeline first). If desktop depends on it, split per-platform instead. Dev configs untouched (dev CSP must keep `'unsafe-inline'` for Vite — known gotcha).

## Phase 3 — Central route-security matrix (P2)
1. Generalize the existing `server/tests/adminRouteSurfaceSecurity.test.js` pattern into one declarative matrix test: every state-changing route in `server/routes/*` must declare expected auth middleware, CSRF (cookie-session routes), validation, and rate-limit class; assert reality against the inventory.
2. Run it; each genuine gap it surfaces becomes its own small fix + regression proof (one conventional commit per gap, never batched). If zero gaps, the matrix still lands as the ongoing coverage guard the audit asked for.

## Verification ladder (per AGENTS.md)
- After each phase: targeted server tests — `auth.tokens.security`, `authSessionService`, `config.headers.security`, `config.cors-csrf.security`, `rate-limit.bypass.security`.
- After Phase 2: `npm --prefix app test` + `npm --prefix app run build`.
- After Phases 1–3: `npm run security:gitleaks`, `npm run security:auth`, `npm run security:tokens`.
- Final: root tracer `npm test`.

## Constraints / no-go
- No `.env` edits, no live secret rotation (owner-only, console), no deploy/purge/migration commands, no history rewrite.
- **Out of scope:** splitting the 2,000-line auth files or other complexity churn — driver is security gaps; mention-only for anything unrelated found.

## Residual risks
- Session persistence changes login longevity UX (reversible).
- CSP change could break desktop flows if desktop consumes web-host CSP — verified before editing; if ambiguous, split config rather than risk it.
- Route matrix may expose real unguarded routes — each fixed individually with proof, not silently.
