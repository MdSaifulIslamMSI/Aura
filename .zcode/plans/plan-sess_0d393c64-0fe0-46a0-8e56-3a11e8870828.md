## Batch A — Server runtime fixes (code + tests)

**A1. Stop duplicate background workers under split runtime** (P1)
- `server/index.js`: the worker-start block (~line 941) runs unconditionally. Gate the poll workers (`startPaymentOutboxWorker`, `startOrderEmailWorker`, `startCommerceReconciliationWorker`, `startAdminAnalyticsMonitor`, `startEmailOpsMonitor`, `startStatusMonitorWorker`, `startCatalogWorkers`) on `!splitRuntimeEnabled` (const already exists at line 266). Keep FX scheduler, Redis, `ensureSystemState`, catalog startup check, model warmup running in both roles (readiness depends on them).
- `server/workerProcess.js`: add `unhandledRejection`/`uncaughtException` fail-fast handlers (log + delayed exit, same pattern as `index.js:1004-1023`); call the `stop*` worker functions in its shutdown handler before closing the health server.
- Verify: new test asserting worker-start is gated when `SPLIT_RUNTIME_ENABLED=true` (mock the start functions / assert via exported helper if needed); existing tests stay green.

**A2. HTTP socket timeouts** (P1)
- `server/index.js`: after `server.listen`, set `httpServer.keepAliveTimeout = 65000` and `httpServer.headersTimeout = 66000` (must exceed CDN/edge origin idle to kill the keep-alive 502 race; values overridable via env). No changes to existing request-timeout middleware.
- Verify: unit test asserting the exported server (or a created test server via same helper) has the timeouts set; grep confirms no other http server instances missed.

**A3. Webhook concurrent-delivery dedupe** (P1)
- `server/services/statusWebhookService.js` `recordWebhookEvent`: wrap `StatusWebhookEvent.create` in try/catch for E11000 (code 11000) → re-read existing by idempotencyKey, bump hitCount, return `{ duplicate: true }`. Mirrors the existing PaymentIntent pattern at `paymentService.js:2194`.
- Verify: new test firing two concurrent `handleStatusWebhook` calls with same eventId — both resolve, no E11000 escape, one `{duplicate:false}` one `{duplicate:true}`. `jest.setTimeout(30000)` (DB-backed).

**A4. Boot-time index sync for critical models** (P1 — the coupon double-redemption backstop)
- Prod has `autoIndex:false`; only Product/SystemState are synced. Add a curated `syncIndexes()` pass at startup for critical integrity models: CouponRedemption, StatusWebhookEvent, PaymentIntent, User, OtpSession, Cart, Order (exact list confirmed against models at implementation). Fail-closed: startup logs `server.index_sync_failed` and readiness reports degraded if unique-index creation fails (dupes present) — matches existing fail-closed readiness design.
- Also register the CouponRedemption unique index as the **first migration** in `server/migrations/index.js` (exercises the runner; idempotent createIndex).
- Verify: `npm --prefix server run migrate:status` shows 1 registered entry; new unit test for the sync helper; CI `node scripts/check-test-tiers.cjs` still passes.

**A5. COD fallback coupon correctness** (P1)
- `server/services/orderPlacementService.js` (~290-294, fallback path): when `CouponRedemption` insert fails (E11000/concurrency) in the non-transactional path, abort placement with 409 (rollback already-applied stock decrement if feasible with existing helpers; minimum: do NOT apply the discount without a redemption row). Document the stock-crash window as a known shared-tier limitation in `docs/database-audit-2026-09-07.md` residual risks (no speculative saga work).
- Verify: new test on the fallback path (env-gated like existing transaction tests): concurrent redemption → second placement rejected, no discount-without-row.

**A6. TTL retention migration** (user-approved)
- Second/third entries in `server/migrations/index.js`: TTL indexes on the unbounded collections — proposed: SecurityEvent 180d, EmailDeliveryLog 90d, UserNotification 180d, AdminNotification 180d, AssistantThreadMessage 180d, StatusAuditLog 180d, ProductGovernanceLog/UserGovernanceLog 365d, PaymentEvent 365d (money data longest). Timestamp field per model verified at implementation; durations documented in the migration descriptions + DB audit doc.
- Verify: `migrate:status` lists them pending then applied against local Mongo; TTL `expireAfterSeconds` asserted in a DB-backed test.

**A7. `db:doctor` health command** (new, small)
- `server/scripts/db_doctor.js` + root/package script `db:doctor`: read-only check that critical unique indexes + TTLs exist and `migrate:status` is clean; non-zero exit on gap. This is the repeatable before/after check for A4/A6 and the prod index verification.
- Verify: run against local test Mongo (expect pass), and against a Mongo missing an index (expect fail).
